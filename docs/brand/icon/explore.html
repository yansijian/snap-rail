snap-rail · 图标选型

不做导轨，做接合部：一台底座，和一个能从它上面摘下来的部件。

  • 1024 网格，圆角 228
  • 缝宽固定 64（16px 上的 1px）
  • 颜色只取出厂钴蓝 token
  • 不画齿轮、电路、状态灯
背景
E1

一轨三模

一条轨道上装着三个模块，最右边那个正被拔起来

轨道 832×120 · 模块 176/240/176×420 · 缝 64 · 抬升 64

它说了什么
  • 轨道、模块、空位：一眼是“底座上装了一排模块”。
  • 最右那块抬起来，方向就是拔出去，插拔动作看得见。
  • 中间那块是钴蓝：三个里有一个是“当前这个”。
它没说清的
  • 模块数量一多，16px 会糊；需要单独的 16px 画法（两块）。
  • 抬起来的那块也可能被读成“掉落”，要靠间隙和位置站稳。
E2

一轨四模

四个模块排满一条轨道，中间那块亮着

轨道 832×120 · 四块 160×400 · 缝 64

它说了什么
  • 排满的轨道最能说明“一切皆插件”：这里已经有四块。
  • 一块亮着、三块沉着，主次和数量都在。
它没说清的
  • 四块在 16px 必然糊成一条带齿的横杠。
  • 间距一致，缺一点“可以被换掉”的动感。
E3

一轨两模

一条轨道，两块模块：一块在位，一块空位

轨道 832×120 · 两块 200×440 · 缝 160

它说了什么
  • 最少的信息量：底座 + 两块。小尺寸最稳。
  • 中间那道大空隙读作“还能再装”，留了余地。
它没说清的
  • 两块太少，读不出“插件系统”，更像“两个面板”。
  • 空位是留白不是形状，可能只是被当成排版。

上一轮我砍得太狠了：两块方块并排、一大一小坐着——语义全丢了，看不出“插件”。这一轮把信息加回来：一条底座 + 一排模块。轨道有明确的两端，模块是同一个规格，间距相等，所以读的是“体系”而不是“数据”。被淘汰的还有：机架抽拉（读成抽屉柜）、悬浮对槽（读成下载按钮）、三块不同高（读成柱状图）。
