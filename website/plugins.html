插件生态

每一枚插件都是同格式的 zip：精简 manifest + 构建好的宿主面（与渲染面），经设置页预检确认后落进 <home>/plugins/ 即时挂载。每张卡片都能直接下载 zip——在联网 PC 下载、拷进内网、拖入终端安装。 组合套件见组合套件页。

静态插件源

插件源 = 任意静态目录（index.json + 插件 zip，下载带 sha256 完整性校验），官方源就是 主仓的滚动 Release。 没有集中市场仓：社区作者在自己的仓库发布并签名，用户把作者 Release 地址加为插件源即可。

community

社区插件怎么发现

社区作者按同一套约定发布：源码在自己的 GitHub 仓库、用作者自己的 Ed25519 密钥签名、发布为自仓滚动 Release，并给仓库打上 snap-rail-plugin topic。发现方式是开放的—— 在 GitHub topic 里浏览，或从作者 README 拿到 Release 地址，然后在终端「插件」页的源设置里添加。 官方这里不维护名单、不做 PR 上架，也不转存社区 zip。

    for developers

    开发自己的插件

    能力缝三件套齐备再动手：Service Definition / Provider / Consumer。驱动是纯协议适配器，照抄 driver-modbus；渲染面必须是 plugin-kit clientBundle 产出的 CJS 工厂包。独立仓库用 @snap-rail/plugin-sdk 与 snap-rail-plugin CLI 打包签名，发布成自己的滚动 Release， 再给仓库打上 snap-rail-plugin topic——不需要 PR 到主仓， 命名也不得占用 @snap-rail/*。缝目录与开发配方见 architecture.md。

    插件开发指南 → architecture.md → 
    # 插件作者：在空目录初始化（driver/store-provider/ui-view/... 任选模板）
mkdir my-plugin && cd my-plugin
pnpm add -D @snap-rail/plugin-sdk
pnpm exec snap-rail-plugin init . --template driver

# 构建 + 用你自己的密钥签名打包
pnpm run build
pnpm exec snap-rail-plugin pack . --sign-key release.private.pem --key-id my-key

# 发布：把 dist/*.zip 传到你仓库的滚动 Release（tag: feed）
# 再给仓库打 topic: snap-rail-plugin
