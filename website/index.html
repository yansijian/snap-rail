为什么是 snap-rail

传统工业终端软件的四个僵局，对应底座的四条解法——每一条都不靠闭源魔法。

僵局

组态软件黑盒

按点位收费、定制走厂商，越用越贵，数据与界面都锁在别人家。

snap-rail

开源底座

Apache-2.0 开源；不复现组态画布，界面创新留给社区与 Agent。

僵局

场景烟囱

snap-rail

architecture

一切皆插件

底座是 DIN 导轨：RPC 缝、点表缝、store、audit 是预制卡位；套件、驱动、工具是模块，咔哒一声卡上即跑。

双面插件

一个 zip，两副面孔

宿主面跑在 node 的 Cordis 树上；渲染面是 clientBundle 产出的 CJS 工厂包，经 snap-plugin:// 特权协议进浏览器图。

文件即接口

plugins.yml 一个入口

页面按钮、手编、Agent 编辑的是同一个文件，watch 热重载立即生效。 

plugins:
  '@snap-rail/suite-terminal-ops':
    enabled: true
坏配置安全

车间不因 YAML 停机

坏文件保持旧插件树继续运行并报错——现场第一，配置错误不配当停机理由。

底座 · 设备管理

设备、组、点，一张表管到底

驱动只负责协议：上交 zod schema 与 createConnection，方言表单由底座 SchemaForm 渲染。连接 LED 红绿即览、组健康灯分级、点表实时值滚动——驱动零渲染端代码、零自有存储。

open source

开源，且值得托付

Apache-2.0 vendored Cordis · 上游 MIT 在 GitHub 上阅读源码

权限明示

安装前 inspect 预检报出名称、版本、类型与权限声明——装什么、能干什么，白纸黑字。

分库隔离

每命名空间一个独立的 SQLite 库文件，文件即隔离边界；跨命名空间协作只能走服务，永不共享表。

审计追踪

append-only JSONL 审计日志，每个业务动作带 actor 记录在案，事后可查、不可篡改。

roadmap
